  • Q4 - Does model cohice effect the cost of callign /compact - Yes
    • /compact is one extra API request: it reads the whole context and writes a summary, and the summary replaces the history
    • on the model you’re already on with a warm cache it’s cheap: the read is a cache read, so the cost is mostly the summary output (500k on Opus ≈ $0.10 read + ~$0.20 summary)
    • switching to a cheaper model just to compact is a model switch first, so it pays a full cold write of the whole context before the summary (500k on Opus ≈ $4). Never worth it
    • compacting a cold session pays the full write too, because there is no cache to read. That’s when /compact costs the most
    • so: compact on the current model, while warm, at a natural break. The model’s price matters far less than the TTL state
  • Q5 - what about cahce and idle sessions?
    • the cache has a timer called TTL (Time To Live): how long it survives without being used
    • on a subscription the main conversation gets 1 hour; on an API key or usage credits it’s 5 minutes
    • only an API request refreshes it. Typing, /model, /usage, editing files: none of these count
    • once it runs out the cache is cold (gone). Idle time itself costs nothing
    • the cost lands on the next request: a full cache write of the whole context, the same bill as a model switch (500k on Opus ≈ $4, on Fable ≈ $10)
    • the status line now shows the countdown (cache 41m, then cache cold), so you can see it before you send
    • best practice, before stepping away: /compact at a natural break while warm. It costs cents, and the cold return then rewrites ~30k instead of 500k. Claude Code can do this for you on idle (idleCompaction)
    • best practice, coming back cold: /clear if the task changed (write the gist yourself; asking Claude for a handoff is itself a full cold write). If you need the history, just continue and pay once. Never /compact cold
    • cold is also the free moment to switch models: you pay the full write either way, so pick the model you want for the next stretch

Ref 1 - experiment: does /model send a request?

Full protocol and raw output in Experiments below. Run in this session, on a Max subscription, 146k context, Opus 5.5 → Fable 5.1.

Result: /model is free. The cost lands on the next message, as a full cache rewrite on the new model.

Entry Model Cache write Cache read
baseline reply opus-5-5 417 146,397
/model fable local command, no API call - -
/usage local command, no API call - -
check reply fable-5-1 141,559 0
  • The two slash commands are stored in the transcript as local_command entries with no token usage. /usage before and after the switch showed the same miss count and no Fable line.
  • The first Fable reply wrote the whole 141k context to a 1-hour cache and read nothing. At API prices that’s about $2.80 for one message, against about $0.03 for the Opus reply just before it.
  • Bonus finding: /usage reported the session’s only other miss as “idle past the 1h TTL, 82.7k tokens re-cached”. That is Q5 observed: an idle gap over an hour cost one full context rewrite.
  • Bonus finding: the session cost line matched the price table to the cent (4.6m reads × $0.20 + 194k writes × $8 + 25.7k output × $20 ≈ $2.98 vs $2.99 shown), so 1-hour cache writes are billed at 2× input.
  • Bonus finding: a switch also changes the system prompt. Claude Code tells the agent which model it is and rewrites the commit attribution line, so the prefix is not byte-identical across models.
